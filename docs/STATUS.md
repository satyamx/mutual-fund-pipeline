|---|---|---|

So v2 is the better model; the lower headline is the **old estimate having been optimistic on a small, kindly-posed test set**. Both remain weak — that is unchanged and is not being dressed up. Note the like-for-like table is a **diagnostic, not a validation**: v2's reported number stays the once-forced 0.558.

**Why the holdout was re-forced.** Reusing the v1 stamp would have been the actual dishonesty — it describes a different target on a different population. It was re-evaluated **exactly once**, with the outcome committed to in advance. `mf_model.MODEL_VERSION` must be bumped on every such refit: `mf_ledger` stamps it as `model_id` and `mf_eval` segments outcomes by it, and v2 initially shipped stamped `phase_b_v1_cohort` — caught and fixed before release.

**✅ Calibration fixed — but the FIRST fix was itself an overclaim, and the review caught it.** Isotonic returned a flat `0.0` over any calibration region with no positives, so 47 of 120 live funds under v1 (27 of 348 under v2) were told their probability was literally zero.

- **`phase_b_v2_1` (superseded within a day)** floored the map at `min(0.01, 3/n)` using the rule of three over the WHOLE 7,268-row calibration slice → `eps = 0.000413`. It removed the literal `0.0` and passed the new guard, so it looked complete. It was not: the flattened region held **6 samples with 0 positives**, whose honest rule-of-three bound is `3/6 = 0.50`. The shipped number was three orders of magnitude tighter than its own evidence.
- **The obvious repair is worse, and was measured before being rejected.** Flooring at that block's real bound (0.50) pins **98% of all predictions at the floor** and collapses AUC from 0.609 to **0.514**. Reported here so nobody re-derives it.
- **`phase_b_v3` fixes the root cause instead:** a 6-sample block should never be a block. PAVA runs, then blocks below `MIN_CAL_BLOCK=30` are **merged into a neighbour** (monotone by construction — pooling adjacent blocks yields a mean lying between them). Every knot now carries **>=30 observations**, and the artifact ships a `support[]` array so the claim is auditable rather than trusted.

**Measured v2_1 → v3:** AUC 0.609360 → **0.610156** (calibration overfit slightly reduced), Spearman 0.9925, min probability 0.000413 → **0.0606 backed by 33 observations**, and distinct outputs **53 → 23,058** — the near-binary output was an artifact of the step function discarding the model's own ordering inside each step, not a property of the model. **The reported holdout AUC is unaffected:** `block_metrics` scores `p_raw`, never the calibrated value, so no holdout re-evaluation was needed or done. `mf_infer --selftest` now rejects any shipped artifact with a 0/1 endpoint **or** a block thinner than `MIN_CAL_BLOCK`.

## Verdict rule + coloring thresholds (as implemented, `RecommendationEngine.run`)
Metric coloring `_band(x, good, bad, higher_better)` → green/red/amber, grey if n/a:
- `cagr` ≥0.10 green / ≤0.06 red · `excess_cagr_3y` ≥+0.01 / ≤−0.01 · `sortino_3y` ≥0.75 / ≤0.0 · `max_dd_3y` ≥−0.20 / ≤−0.35 (shallower better) · `consistency` ≥0.60 / ≤0.40 · `expense` ≤0.010 green / ≥0.020 red (lower better) · `compliance` = red if any critical, amber if warnings or (active & holdings missing), else green · `screen_score` ≥65 green / <45 red / else blue.
- Core metrics counted = [cagr, excess_cagr_3y, sortino_3y, max_dd_3y, consistency].
- **Rule:** `SELL` if (any critical breach OR any regulatory red_flag OR reds≥3 OR (reds>greens AND screen_score red)); else `BUY` if (greens≥3 AND reds==0 AND screen_score≠red); else `HOLD`.
- Return adds: `verdict, verdict_color, verdict_caveat, metric_colors`. Thresholds are TUNABLE defaults — revisit once the cohort percentile is wired into the verdict.

## Observation worth a decision (not yet a blocker) — the calibrated probability is nearly binary in production
The shipped `cohort_q1` head is isotonic-calibrated with 15 distinct output levels, and on the live 136-fund population it collapses much further: the 120 ledger rows carry only **11 distinct probabilities**, with **57 funds at exactly 0.2470** and **47 at exactly 0.0**. That is inherent to isotonic regression on a small calibration slice, not a bug in this session's work — but two things follow. (1) Emitting a literal `probability: 0.0` asserts a fund has *no* chance of landing in its cohort's top quartile, which the base rate (0.323) and a weak AUC (~0.578) cannot support; a floor, or shipping the rank rather than the point estimate, is the honest option. (2) `cohort_percentile` is computed by ranking within cohort, so with 104 of 120 funds sharing two values it is mostly resolving ties — the percentile looks more discriminating than the underlying score is. Neither is a correctness defect; both are presentation choices the app inherits.
